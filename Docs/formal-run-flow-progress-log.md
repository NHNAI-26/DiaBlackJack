> **현행 상점 규칙 변경 안내 (2026-07-29)**
> 카드 슬롯은 각각 재고 1개지만 방문 전체 구매 횟수에는 상한이 없다. 라이터와 위스키는 방문당 각각 1회 이용할 수 있고 같은 방문에서 둘 다 가능하다. 둘 중 하나 이상 이용한 방문은 다음 상점의 두 서비스 가격을 함께 한 단계만 올린다. GameScene MVP의 기본 2골드·상승 +1은 임시값이다.

> **Notion v0.7 골드 영향 (2026-07-29)**
> 적이 6종으로 재구성되어 RF-00의 3·3·4·6·10은 과거 임시값이 되었다. 여섯 지급량은 미정이며 코드·테스트는 변경하지 않았다. HONG의 실제 RF 구현 기여는 여전히 미착수다.

## 1. 기록 원칙

- 계획과 실제 구현을 분리한다.
- HONG이 구현하기 전에는 완료 기여로 기록하지 않는다.
- 각 단계마다 작업자, 변경 파일, 직접 결정한 문제, 대상·전체 테스트와 실제 화면 결과를 남긴다.
- AI 초안과 사람의 검토·결정을 구분한다.
- 전투·보상·상대 선택 내부 변경은 이유와 이천서 검토 여부를 기록한다.

- 최신 `rule.md`, 전체 기획, SP·RW·EUI 문서와 현재 `PlayerRunState`, `StageProgressionSession`, Runtime·Controller를 대조했다.

## 5. RFM01 GameScene 상점 규칙 선반영

### 5.1 수행 내용

- 카드 구매는 구매한 슬롯만 `SOLD OUT`으로 막고 방문 전체 구매 플래그를 두지 않아, 골드가 충분하면 남은 슬롯을 모두 살 수 있게 했다.
- 라이터와 위스키에 서로 독립된 방문당 1회 플래그를 두어 같은 상점에서 둘 다 이용할 수 있게 했다.
- 둘 중 하나 이상 이용한 방문을 닫을 때 가격 단계를 정확히 1 올리고 다음 방문의 두 서비스 가격에 함께 적용했다. 둘 다 이용해도 한 단계만 오르며, 미이용 방문은 유지한다.
- 새 런 재시작은 골드·상점 제안 순번·가격 단계·방문 플래그를 모두 초기화한다.
- 일반 상점과 라이터 카드 선택 화면에 `나가기` 버튼을 연결했다.
- GameScene MVP의 두 서비스 기본 가격 2골드와 이용 방문당 +1골드는 Inspector에서 조정 가능한 임시값으로 두었다.

### 5.2 변경 파일

- `Assets/01. Scripts/GameScene/ShopController.cs`
- `Assets/01. Scripts/GameScene/GameManager.cs`
- `Assets/06.Packages/Tests/EditMode/CoreLoop/ShopControllerTests.cs`
- 상점·런 관련 기획 문서와 공통 AI·역할 기록

### 5.3 검증

- RFM01 대상 3/3 통과: Unity MCP job `be7463c015f64188a8d6dbccba9526e6`
- 전체 EditMode 626/626 통과: Unity MCP job `1144276f15a64abd90841ce310416ab9`
- GameScene에서 첫 방문 위스키 이용 뒤 다음 방문의 라이터·위스키가 모두 2→3골드가 된 상태를 확인했다.
- 일반 상점의 `나가기`, 라이터 선택 패널의 `CANCEL`·`나가기`, 라이터 호버 `PRICE 3 GOLD`를 실제 Game View에서 확인했다.
- Play Mode 종료 뒤 `GameScene.unity`가 비저장 변경 없이 `isDirty=false`인 것을 확인했다.
- Test Framework 결과 저장 안내 1건과 기존 `ShopItem_Lighter/Body` 음수 스케일 BoxCollider 오류 1건을 분리했다. 신규 스크립트 컴파일 오류와 테스트 실패는 0이다.
- 씬·프리팹·Packages·외부 코드·외부 에셋·오픈소스는 변경하지 않았다.

### 5.4 책임과 경계

최종 기획·코드·화면 승인 책임자는 이천서이며 AI는 구조 대조, 구현, 테스트와 문서 갱신을 보조했다. 이번 작업은 기존 GameScene 독립 상점 MVP의 규칙 보정이다. HONG 담당의 RF-01 골드 정산, RF-02 정식 상점 도메인과 RF-03~RF-05 정식 런 연결은 완료로 기록하지 않는다.

## 7. 인수인계 핵심 계약

1. `StageProgressionSession`은 상대 선택·전투·카드 보상·전투 스테이지를 계속 소유한다.
2. 정식 런 UI는 기존 카드 보상 API를 직접 호출하지 않고 바깥 세션을 사용한다.
3. 카드 선택과 건너뛰기 모두 승리 골드를 한 번 지급한다.
4. 일반전 카드 보상 뒤에는 다음 전투가 아니라 상점을 연다.
5. 상점에서 나간 뒤에만 `TryAdvanceToNextStage()`를 호출한다.
6. 첫 상점 뒤에는 상대 선택, 둘째 상점 뒤에는 고정 보스다.
7. 보스 골드는 기록하지만 상점을 열지 않는다.
8. 상점 변경 영혼·덱은 다음 전투 생성 전에 반영한다.
9. 카드 강화·유물·무작위 사건은 RF에서 선점하지 않는다.
10. 카드 구매는 슬롯별 재고만 제한하고 방문 전체 구매 상한을 두지 않는다.
11. 라이터·위스키는 방문당 각각 1회이며 둘 중 하나 이상 이용한 방문은 다음 상점의 두 가격을 한 단계만 올린다.
12. `나가기`는 무료이고 라이터 선택 상태에서도 사용할 수 있다.
