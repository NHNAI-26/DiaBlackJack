# 카드 콘텐츠 SO 설계

## 목적

일반 카드와 악마 카드의 제목, 설명, 가격, 상점 가중치, 아트를 Unity ScriptableObject로 저작한다. 규칙 실행은 계속 순수 C# Handler가 담당한다.

## 결정

- 일반 카드 15종과 악마 카드 12종은 각각 개별 SO다.
- 한국어 문자열을 직접 저장한다. 로컬라이징 키 전환은 후속 작업이다.
- `Key`는 기존 값 그대로 유지한다. 저장, 보상, 적 덱, 상점은 key 계약을 계속 사용한다.
- 가격은 카드별 `BasePurchasePrice`다. 상점의 후속 할인·증가 규칙이 있을 때만 그 위에 적용한다.
- 일반 카드의 기본 덱 지정은 숫자별 하나다. 자동 카드는 기본 덱에 들어가지 않는다.
- Sprite는 카드 SO가 소유한다. 일반 카드는 스페이드/클로버 앞면을, 악마 카드는 앞면 하나를 가진다.
- CSV와 `Resources.Load`는 사용하지 않는다. 모든 참조는 `CardContentCatalogSO`와 Inspector에서 명시한다.

## 저작 필드

| 종류 | 공통 | 전용 |
| --- | --- | --- |
| 일반 카드 | Key, 한국어 이름·설명, 기본 구매 가격, 상점 가중치 | 숫자, 활성화 방식, 효과 kind, 기본 덱 지정, 스페이드/클로버 Sprite |
| 악마 카드 | Key, 한국어 이름, 기본 구매 가격, 상점 가중치 | 계약 kind, 기본 영혼 비용, 한국어 액티브 효과·대가 설명, Sprite |

`CardEffectKind`와 `DemonContractKind`는 실제 규칙 Handler를 고르는 계약이며, SO 문자열은 UI 표시 전용이다.

## 범위 밖

적 프로필 덱, 전투 보상 후보, 효과 Handler, 다국어 테이블, 저장 schema/revision은 이번 작업에서 데이터화하거나 변경하지 않는다.
