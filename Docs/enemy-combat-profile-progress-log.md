> **겁쟁이 도박사 구현 (2026-07-28)**
> 이천서 책임으로 세부 카드 수량의 합산 오류를 17장에서 18장으로 정정하고, `cowardly-gambler`를 기존 3종을 유지한 네 번째 일반 적으로 편입했다. 최대 영혼 2·일반 보상·빈 악마 덱·합계 14 스탠드·수동 카드 비사용을 구현했고 전용 9/9·전체 534/534·게임 코드 오류 0으로 검증했으며 최종 Test Framework 결과 저장 안내 3건을 분리했다.

> **현행 규칙 이관 안내 (2026-07-21)**
> 아래 적 폴드 관련 결정과 검증은 당시 구현 이력이다. 현행 기획에 따라 적 폴드를 공개 행동·관측 후보·정책·전투 실행에서 제거했고, Unity 전체 EditMode 306/306 통과와 `GameScene` 무변경을 확인했다.

> **해머 대상 이관 결과 (2026-07-22)**
> 아래 EP-04·EP-05의 적 공개 카드 최저 비용 선택은 당시 구현 이력이다. 현행 해머는 플레이어 공개 카드 중 최고 숫자를 대상으로 선택하며 전체 EditMode 308/308으로 검증했다.

> **광신도 계약 연결 결과 (2026-07-23)**
> 아래 EP-00·EP-03의 악마 계약 미구현·제외 설명은 당시 이력이다. DC-07에서 광신도에게만 전용 악마 덱과 `DemonContract` 후보·선택·후속 정책을 연결했고, 다른 적은 계약 덱 없이 기존 정책을 유지한다. 비공개 카드 숫자는 최종 승부 전까지 계약 판단에 사용하지 않는다.

> **광신도 계약 밸런스 결과 (2026-07-23)**
> DC-08에서 400시드 기준 벨페고르 77.5% 편향을 재현하고, 사탄 생존·레비아탄 리볼버 효용 조건과 벨페고르·마몬 결정적 동점 분산으로 교정했다. 100회 자동 전투는 모두 종료됐다.

> **Notion v0.7 재명세 (2026-07-29)**
> 최신 원본은 겁쟁이 도박사 3, 총잡이 3, 광신도 5, 사기꾼 5, 집행자 5, 보스 8 영혼과 전용 덱·능력·악마 운용을 명시한다. 이는 EP-R02 코드와 충돌하며 문서 갱신만으로 구현 완료가 되지 않는다. 기존 테스트 수치는 과거 기준선으로 보존하고 EP-R04부터 새 실패 테스트를 작성한다.

> **세부 결정 완료 (2026-07-29)**
> 이천서가 겁쟁이 공개 합 15 스탠드·수동 카드 15%, 공통 적 체인지 판단, 광신도 계약 성공까지 재시도, 집행자 최초 배분 전 독극물 혼합, 보스 영혼 5·2 계약 전환과 프로필별 골드 3·4·6·7·9·15를 확정했다. 값·덱·표시명·아스모데우스 제한은 EP-R04, 일반·엘리트 특수 정책과 상태는 EP-R05, 보스 계약 단계는 EP-R06에서 구현했다. 골드·저장·정식 런 UI는 HONG RF 범위로 분리한다.

## 1. 기록 원칙

- 계획과 실제 구현을 구분한다.
- 문서 단계는 코드 구현 완료로 기록하지 않는다.
- 적 AI가 사용한 공개·비공개 정보 경계를 단계마다 기록한다.
- 변경 파일, 테스트, 실제 전투, 씬·패키지·외부 에셋 변경 여부를 남긴다.
- 상대 선택·아트 담당자의 파일을 이천서의 실제 기여로 기록하지 않는다.
- AI 입력 원문은 목적, 지시, 결과와 사람의 결정으로 정제한다.
- 기획·코드·검증의 최종 책임자는 이천서로 기록한다.
- 사용자의 요청 전에는 스테이징·커밋·푸시하지 않는다.

## 3. 착수 기준선

### 3.1 완료된 선행 작업

- 코어 루프 1~4단계 완료
- 런·스테이지 SP-00~SP-04 완료
- 전투 행동 BA-00~BA-05 완료
- 카드 사용 CU-00~CU-06 완료
- 전투 보상 RW-00~RW-05 완료
- RW-05 기준 CoreLoop 122/122, StageProgression 65/65, 전체 EditMode 187/187 통과
- `CoreLoopTest`, `StageTest` 씬 문제 0과 최종 Console Error/Warning 0 확인

### 3.2 EP-00 시점 코드 상태

- `SimpleEnemyPolicy`는 적 자신의 합계만 보고 16 이하 히트, 17 이상 스탠드한다.
- `CoreLoopBattle`은 구체 `SimpleEnemyPolicy`에 의존한다.
- 적 차례의 카드 사용·폴드·체인지·계약 API는 없다.
- 수정 구슬·위협용 해머·리볼버·보위 나이프의 플레이어 효과 처리기는 존재한다.
- 거짓말 탐지기와 악마 계약은 현재 카드 카탈로그·처리기에 없다.
- `StageBattleFactory`는 적 표준 덱과 스테이지 최대 영혼으로 전투를 만든다.
- `StageProgressionSession`에는 전투 생성과 보상 등급 주입 경계가 있다.
- 상대 후보와 선택된 적 프로필 키는 아직 없다.

### 3.3 협업·Git 주의사항

- `StageProgressionSession.cs`, `StageBattleFactory.cs`, 진행 UI와 테스트 씬은 상대 선택 통합 시 충돌 가능성이 높은 공유 파일이다.
- 공유 파일은 EP-06 전에 담당자를 한 명 정하고 동시 수정하지 않는다.
- 아트 담당 경로와 Unity 자동 생성 솔루션 변경은 EP 문서 커밋에서 제외한다.
- 현재 Unity가 자동 갱신한 `DiaBlackJack.slnx` 변경은 의미 있는 EP 변경으로 포함하지 않는다.

EP-06은 공유 진행 런타임만 최소 변경했고 씬 파일을 수정하지 않았다. 상대 선택 담당은 이후 선택 결과의 `BattleProfileKey`를 `StageDefinition.CreateForEnemyProfile(...)`에 전달하면 된다.

### 7.1 위협용 해머 대상 변경 이관

- 선택 옵션의 소유자를 적에서 플레이어로 바꾸고 카드 ID 충돌 시에도 선택 종류로 상대 손패를 조회한다.
- 집행관과 최종 보스는 플레이어 공개 카드 중 숫자가 가장 큰 대상을 고른다.
- 스탠드 여부와 무관하게 공개 카드 제거를 평가하며, 스탠드 상태에서는 취소·비공개 교체 후속 효과를 함께 처리한다.
- 적 정책·카드 효과·GameScene 표시 회귀를 포함한 Unity 전체 EditMode 308/308을 통과했다.

### 7.2 EP-R04 개정 프로필 데이터 이관

- `EnemyCombatProfileCatalog`의 최대 영혼을 겁쟁이 3·총잡이 3·광신도 5·사기꾼 5·집행자 5·최종 보스 8로 맞췄다.
- 총잡이 14장, 광신도 20장, 사기꾼 18장, 집행자 19장, 보스 25장 전용 덱을 정의별 정확한 수량으로 고정했다. 사기꾼은 문서의 세부 수량 합계가 18장이므로 잘못 적힌 총수 17을 정정했다.
- 겁쟁이 도박사는 공개 합 15부터 스탠드하고, 집행관 표기를 `집행자`로 통일했다.
- 보스 최대 영혼 8에 맞춰 기존 전투 정책 표시 구간을 8~6·5~3·2~1로 호환했다. 시작·영혼 5·2 고정 계약 전환은 EP-R06 범위다.
- 아스모데우스 제한을 숫자 7 이하로 올려 해머 6·리볼버 7 제한과 리볼버 8 허용을 고정했다.
- 광신도 영혼 5 이관으로 과거 공용 악마 덱의 사탄이 생존 가능한 선택이 되어 자동 전투가 정체되는 충돌을 발견했다. 최신 기획상 광신도 후보가 아닌 사탄을 선택하지 않도록 최소 안전 경계를 적용했으며, 벨페고르·바알제붑·벨리알 전용 구성과 성공까지 재시도는 EP-R05/DC-R06에 남겼다.
- EPR04 14/14, CoreLoop 451/451, StageProgression 189/189, 전체 EditMode 640/640을 별도 복제본의 Unity Test Runner로 통과했다. GameScene·씬·프리팹·Packages·외부 에셋·오픈소스는 변경하지 않았다.

### 7.3 EP-R05 특수 정책·상태 이관

- 프로필 데이터에 적 체인지 비용 모드, 악마 계약 키/후보 수와 집행자 독극물 주입 플래그를 추가했다.
- 실제 스테이지 프로필 전투만 공통 적 체인지를 활성화하고 직접 생성 전투·독립 GameScene은 기존 기본값을 유지했다.
- 겁쟁이는 사용 가능한 수동 카드를 결정적 15%로 사용하며, 광신도는 세 전용 악마 중 조건에 맞는 계약을 성공할 때까지 우선한다.
- 모든 프로필 적은 자기 비공개 역할이 앞면이거나 전체 합이 21 초과일 때 체인지한다. 일반 비용은 0부터 누적하고 사기꾼은 매회 1을 지불한다.
- 집행자는 파이몬 단일 후보를 계약하고 매 라운드 배분 전에 플레이어 덱에 독극물을 추가한다. 주입 카드는 전투 중 누적되고 종료 시 전량 제거된다.
- 강제행동 우선순위와 공개 관측을 테스트로 고정하고 미공개 비공개 카드의 숫자·ID·덱 순서를 AI에 노출하지 않았다.
- 정책 12/12, CoreLoop 466/466, StageProgression 189/189와 전체 EditMode 655/655가 통과했다. `GameScene`·UI·씬·프리팹·Packages·외부 에셋·오픈소스는 변경하지 않았다.

### 7.4 EP-R06 보스 고정 계약 단계 이관

- 실패 테스트를 먼저 작성해 보스 프로필에 고정 단계 데이터와 전투 전환이 없음을 확인했다.
- `FixedDemonContractPhaseDefinition`을 추가해 첫 단계 `null`과 후속 영혼 임계값, 활성/폐기 키, 내림차순·고유 카드 불변식을 검증했다.
- 최종 보스의 악마 덱을 바포메트·마몬·아스모데우스·레비아탄·아자젤·루시퍼로 구성하고, 프로필→전투 설정→`StageBattleFactory`→`CoreLoopBattle` 경계로 전달했다.
- 전투 시작에는 바포메트/마몬을 처리하고 생존 영혼 5에서 아스모데우스/레비아탄, 2에서 아자젤/루시퍼를 처리했다. 이전 활성 계약은 버린 더미로 이동한다.
- 한 피해가 두 후속 임계값을 넘으면 순서대로 모두 전환하며, 회복은 역행하지 않고 치명 피해는 후속 계약을 활성화하지 않는다.
- 고정 단계 보스는 일반 적 계약 API를 사용할 수 없어 영혼 비용·후보 선택·기본 계약 횟수를 소비하지 않는다.
- 기존 `DemonContractPresenter`에 바포메트·아스모데우스·아자젤의 현재 구현 효과 문구를 연결했다. `GameScene`이나 Unity 직렬화 파일은 수정하지 않았다.
- EPR06 10/10, CoreLoop 476/476, StageProgression 189/189와 전체 EditMode 665/665가 통과했다. 최초 9개 실행의 테스트 기대 2건은 라운드 단위 `PublicActionHistory`를 전투 누적으로 가정한 테스트 오류로 확인해 계약 상태와 현재 라운드 전환 순서 기준으로 교정했다.
- 프로필별 골드 정산·저장·정식 런 UI는 코드에 추가하지 않았으며 HONG의 RF-01 이후 범위로 유지한다. 보스 승률과 단계 체류 시간 플레이 테스트는 후속 밸런스 작업이다.
