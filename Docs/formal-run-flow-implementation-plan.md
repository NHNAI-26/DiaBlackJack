## 1. 실행 원칙

RF-01A·RF-01B는 이천서가 선행 완료했다. HONG은 후속 `RF-02 → RF-03 → RF-04 → RF-05`를 순서대로 구현하고, 각 단계에서 대상 테스트와 전체 회귀를 확인해 진행 기록을 갱신한다. 이천서는 기존 전투·보상·상대 선택 경계 변경과 최종 통합을 검토한다.

## 4. RF-01 — 런 골드와 승리 정산

### 작업

- RF-01A: `PlayerRunState`에 호환 가능한 골드 보유·지급·소비·재시작 경계를 추가한다.
- RF-01B: `GoldRewardCatalog`에 여섯 프로필과 이천서가 확정한 지급량을 등록한다.
- 종료된 승리 전투를 처음 동기화한 뒤 한 번만 골드를 지급하는 정산 경계를 만든다.
- 일반전 승리, 보스 승리, 패배, 중복 동기화와 잘못된 입력을 구분한다.
- UI·상점·씬은 아직 변경하지 않는다.

### 검증 게이트

- 여섯 프로필별 지급량과 `엘리트 > 모든 일반 적`, `보스 > 엘리트`가 테스트로 고정된다.
- 일반전·보스 승리는 지급하고 실패·중복·패배는 지급하지 않는다.
- 재시작 골드는 0이다.
- 기존 전체 테스트가 통과한다.

RF-01 완료 결과: RF-01A는 기존 생성자의 골드 0 호환, 새 생성·복원 경로, 오버플로 없는 지급, 실패 원자적인 소비, 재시작 0 복구와 저장 왕복을 구현했다. RF-01B는 여섯 프로필 카탈로그와 종료 승리 전투 참조당 한 번 지급을 구현했다. RF-01 전체 대상 14/14와 런타임·StageProgression 테스트 어셈블리 컴파일은 성공했다. Unity MCP가 현재 연결되지 않고 Editor가 실행 중이라 전체 EditMode는 미실행이다.

### 권장 커밋 제목

`위험한 상대 선택이 골드 보상으로 이어지게 하다`

## 5. RF-02 — 상점 도메인

### 작업

- 불변 `ShopCardOption`, `ShopOffer`, 거래 결과와 결정적 생성기를 구현한다.
- `CardDefinitionCatalog.All`의 상점 허용 정의에서 자동 발동 카드 5종을 포함한 일반 카드 3장과 악마 카드 2장을 만들고 슬롯별 재고 1개를 관리한다.
- 같은 상점에서 정의 키를 중복하지 않고, 엘리트 승리 뒤에는 높은 등급 일반 카드의 출현 가중치를 높인다.
- 방문 전체 카드 구매 상한을 두지 않아 골드가 충분하면 남은 슬롯을 모두 살 수 있게 한다.
- 라이터와 위스키를 서로 독립된 방문당 1회 서비스로 구현해 같은 방문에서 둘 다 이용할 수 있게 한다.
- 둘 중 하나 이상 이용한 상점을 나가면 다음 상점의 두 서비스 가격 단계를 함께 정확히 1 올린다. 미이용 상점은 유지하고 새 런은 0으로 초기화한다.
- 무료 `나가기`를 일반 상점과 라이터 선택 상태 모두에 제공한다.
- `PlayerRunState`의 카드 제거는 덱 최소 1장과 ID 미재사용을 지킨다.
- Unity UI와 정식 순서는 아직 연결하지 않는다.

### 검증 게이트

- 거래 성공은 비용과 효과를 한 번에 반영한다.
- 부족한 골드·잘못된 대상·같은 슬롯 재구매·같은 서비스 중복 이용은 모든 상태를 보존한다.
- 하나 또는 둘 이용한 방문은 가격 단계가 한 번만 오르고, 미이용 방문은 오르지 않는다.
- 제안은 같은 시드에서 결정적이고 재진입으로 바뀌지 않는다.
- 자동 발동 카드 5종이 결정적 시드 표본에서 모두 출현 가능하며 구매 뒤 다음 전투의 일반 카드 덱에 들어간다.
- 기존 전체 테스트가 통과한다.

### 권장 커밋 제목

`골드를 성장 선택으로 바꿀 상점 거래를 마련하다`

RF-02 완료 결과: 순수 C# `ShopCardOption`, `ShopOffer`, `ShopOfferGenerator`, `ShopVisit`, `ShopTransaction`과 일반 카드 최소 1장을 지키는 제거 API를 구현했다. 대상 11/11과 런타임·StageProgression 테스트 어셈블리 컴파일은 성공했다. Unity MCP 미연결 상태라 전체 EditMode와 실제 화면은 실행하지 않았으며 RF-03에서 정식 순서를 연결한다.

## 6. RFM01 — GameScene 상점 규칙 선반영

### 작업·경계

- 이천서가 현행 `GameScene/ShopController`에 카드 슬롯별 구매, 라이터·위스키 독립 1회, 이용 방문당 공통 가격 단계와 런 초기화를 반영한다.
- `GameManager`의 상점 종료 문구를 `나가기`로 바꾸고 라이터 대상 선택 중에도 같은 종료 입력을 제공한다.
- 이 작업은 현재 GameScene 독립 전투의 상점 MVP만 보정한다. HONG의 RF-01~RF-05 정식 골드·런 상태와 `전투→상점→전투→상점→보스` 연결 완료를 뜻하지 않는다.
- 씬·프리팹·Packages·외부 에셋은 변경하지 않는다.

### 검증 게이트

- 같은 상점에서 카드 슬롯 3개 이상을 연속 구매할 수 있고 구매한 슬롯만 재구매할 수 없다.
- 위스키만 이용한 다음 방문에서 두 서비스 가격이 함께 오르며, 한 방문에서 둘 다 이용해도 다음 상승은 한 단계다.
- 미이용 방문과 새 런 초기화가 가격을 정확히 유지·복구한다.
- 전체 EditMode와 실제 GameScene 상점 화면·Console을 확인한다.

### 권장 커밋 제목

`상점 선택의 자유와 누적 이용 대가를 반영하다`

## 7. RF-03 — 정식 순서 통합

### 작업

- `FormalRunPhase`와 `FormalRunSession`을 구현한다.
- 기존 상대 선택·전투·승패는 `StageProgressionSession`에 위임하고, 정식 런에서는 카드 보상 생성을 우회하는 명시적 완료 경계를 추가한다.
- 일반전 승리 뒤 골드를 정산하고 별도 보상 화면 없이 상점을 연다.
- 첫 상점 나가기 뒤 두 번째 상대 선택, 둘째 상점 뒤 고정 보스로 이동한다.
- 보스 승리는 골드를 결과에 반영하고 카드 보상·상점 없이 런 승리로 마친다.
- 패배와 재시작에서 모든 후속·이전 상태를 차단·초기화한다.

### 검증 게이트

- `전투→골드→상점→전투→골드→상점→보스→RunVictory` 순서와 `RewardSelection` 미진입이 통합 테스트로 고정된다.
- 상점에서 나가기 전 스테이지 인덱스가 증가하지 않는다.
- 상점 변경 영혼·덱이 다음 전투에 반영된다.
- 기존 고정 진행 세션의 회귀가 유지된다.

RF-03 완료 결과: 정식 세션 전용 무카드보상 완료 정책과 전투 결과 알림을 추가하고, 일반전 승리 시 현재 스테이지를 유지한 상점 생성, 나가기 후 다음 전투 준비, 둘째 상점 뒤 고정 보스, 보스 즉시 승리와 세 위치 패배·재시작을 구현했다. 상점 회복·구매 결과가 다음 전투 팩토리에 전달되고 오래된 ID는 무변경 거부된다. RF03 12건과 RF-01~03 누적 37/37, 런타임·테스트 어셈블리 컴파일이 통과했다. Unity MCP 미연결과 실행 중 Editor 때문에 전체 EditMode·실제 씬은 RF-04 이후 재검증한다.

### 권장 커밋 제목

`전투와 보스 사이에 두 번의 상점 흐름을 고정하다`

## 8. RF-04 — 진행 화면과 씬 연결

### 작업

- Runtime이 정식 런 세션을 소유하고 전투 Controller에는 내부 전투 세션을 제공한다.
- Presenter에 골드·상점 후보·가격·가능 여부·최근 거래를 추가한다.
- View와 Controller에 구매·제거·휴식·나가기 입력을 연결한다.
- 상점 중 상대·NEXT STAGE·재시작 입력을 차단하고 정식 런 화면에서는 보상 패널을 표시하지 않는다.
- 첫 상점 뒤 상대 선택, 둘째 상점 뒤 보스 씬 이동을 연결한다.

### 검증 게이트

- 일반전 종료 뒤 골드 결과와 상점이 곧바로 표시되고 보상 후보는 표시되지 않는다.
- 거래 가능/불가 상태와 결과가 실제 데이터와 일치한다.
- 1280×720·1920×1080에서 겹침·잘림이 없다.
- 실제 `StageTest ↔ GameScene` 흐름과 Console이 통과한다. `CoreLoopTest`는 독립 검증 씬으로 유지한다.

RF-04 코드 결과: Runtime이 현재 저장 세션을 `FormalRunSession`으로 재결합하고 CoreLoop에는 내부 전투 세션을 제공한다. Presenter·View·Controller에 골드, 상대별 예상 골드, 카드 5장 구매, 라이터 카드 제거, 위스키 회복, 가격 단계와 나가기를 연결했으며 정식 경로의 보상·NEXT STAGE 입력을 숨겼다. RF04 6개 테스트의 컴파일과 Unity 비의존 5개 실행, RF-01~04 비Unity 누적 42/42가 통과했다. Unity MCP의 `8080/mcp`는 TCP 연결되지만 initialize handshake가 실패하고 현재 작업에 호출 도구가 없어 Controller EditMode 1건·두 해상도·씬 왕복은 아직 완료 게이트로 표시하지 않는다.

RF-04 GameScene 후속 결과: `GameManager`가 Runtime의 실제 전투를 채택하고 모든 행동을 진행 세션에 위임하도록 연결했다. 정식 런에서는 승리 골드를 HUD에 표시하고 독립 상점의 중복 지급을 막은 뒤 진행 씬의 정식 상점으로 돌아간다. `StageTest`의 전투 목적지와 Build Settings를 `GameScene` 기준으로 갱신했으며 단독 GameScene·CoreLoopTest는 회귀용으로 보존한다.

### 권장 커밋 제목

`정식 런의 골드와 상점을 기존 진행 화면에 잇다`

## 10. 변경 제한

- 전투 판정, 적 AI와 카드 효과는 RF에서 수정하지 않는다. 기존 RW 풀과 상태는 삭제하지 않고 정식 런에서만 사용하지 않는다.
- 골드 지급량은 새 카탈로그에 두고 적 프로필 생성자에 억지 필드를 추가하지 않는다.
- 상점 카드 구매는 `CardDefinitionCatalog`의 상점 허용 정의를 읽고 전투 보상 카탈로그·상태를 재사용하지 않는다.
- 카드 강화·유물·무작위 사건을 빈 구조로 미리 만들지 않는다.
- 다른 팀원의 미완료 변경을 되돌리지 않는다.
- 기존 공개 API 변경이 필요하면 진행 기록에 이유·대안·이천서 검토를 남긴다.
