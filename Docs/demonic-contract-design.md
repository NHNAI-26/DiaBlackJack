## 1. 문서 목적

이 문서는 `rule.md`의 악마 계약을 현재 전투·카드·런 구조에서 단계별로 구현할 수 있도록 구체화한다. 계약은 영혼을 직접 지불해 전투 규칙을 바꾸는 고위험·고효율 행동이며, 일반 카드 사용과 구분되는 DiaBlackJack의 핵심 차별점이다.

문서에 없는 세부 처리는 다음 세 종류로 구분한다.

- **현행 확정:** 원본 규칙과 전체 기획이 일치하거나 이천서가 이미 명시한 사항
- **프로토타입 결정:** 첫 구현과 테스트를 위해 이 문서에서 임시로 고정한 사항
- **기획 확인 게이트:** 구현 전에 이천서가 최종 승인하거나 플레이 테스트로 조정해야 하는 사항

AI는 규칙·코드 구조 대조와 문서 초안을 보조했다. 기획 승인과 변경 결정 책임자는 이천서다.

## 3. 핵심 기획 결정

| 항목 | 현행 기준 |
| --- | --- |
| 계약 진입 | 플레이어 차례에 테이블의 별도 악마 카드 덱을 선택한다. |
| 기본 비용 | 영혼 1 |
| 비용 조건 | 현재 영혼이 비용보다 많아야 한다. 기본 비용 1일 때 영혼 2 이상이어야 한다. |
| 기본 횟수 | 전투 스테이지당 1회 |
| 런 시작 악마 | 서로 다른 2장 중 1장을 반드시 선택해 시작 악마 덱에 넣는다. |
| 시작 덱 최소치 | 선택한 악마로 최소 1장을 보장하며, 시작 선택은 계약 비용·횟수를 소비하지 않는다. |
| 후보 | 악마 덱에서 현재 제시 가능한 카드 중 최대 2장 |
| 선택 | 2장이면 1장 선택, 1장이면 해당 1장만 제시, 0장이면 계약 불가 |
| 미선택 카드 | 미선택 카드가 있으면 해당 전투의 악마 버린 더미로 보낸다. |
| 덱 표현 | 일반·악마 덱은 나란히 두고 맨 위에 각각 전용 카드 뒷면을 표시한다. |
| 덱 정보 | 두 덱을 호버하면 포함 카드 목록을 표시하되 실제 순서는 숨긴다. |
| 후보 연출 | 중앙에 앞면 카드 최대 2장을 `발견` 방식으로 펼치고 호버 시 능력·대가를 표시한다. |
| 활성 계약 | 선택 카드를 플레이어 앞에 일반 카드 크기의 앞면 카드로 놓고 호버 시 능력·대가를 표시한다. |
| 지속 범위 | 선택한 상대와의 전투 전체, 즉 여러 라운드에 걸쳐 유지하고 전투 종료 시 해제한다. |
| 행동 소비 | 계약 선택과 즉시 효과 처리는 플레이어의 정상 행동 1회를 소비한다. |
| 취소 | 비용 지불 전 확인창은 닫을 수 있다. 비용 지불 후 후보가 공개되면 취소·환불할 수 없다. |
| 개별 대가 | 영혼을 0까지 감소시킬 수 있고, 0이 되는 순간 즉시 전투 패배한다. |
| 선택형 문구 | `할 수 있다`는 계약 소유자가 실행 여부를 선택한다. |
| 버스트 범위 | 숫자·카드·악마·계약 효과와 특수 패배 조건의 버스트를 모두 포함한다. |
| 생성 카드 합계 | 숫자가 적힌 계약 생성 특수 카드는 합계에 포함한다. |
| 동일 악마 중첩 | 추가 계약에서 같은 악마를 다시 선택할 수 있으며 각 계약은 별도 인스턴스다. |
| 임시 카드 수명 | 생성·이동·추방 상태는 현재 전투의 여러 라운드에 유지하고 전투 종료 시 원상복구한다. |
| 적 계약 | 플레이어와 같은 비용·선택·대가·중첩·정리 규칙을 사용한다. |
| 1차 구현 악마 | 사탄, 벨페고르, 마몬, 레비아탄 |

`현재 영혼 > 비용`은 체인지와 동일한 엄격 조건이다. 계약 시작 비용 자체가 영혼을 0으로 만들 수는 없지만 이후 악마의 개별 대가는 영혼을 0까지 감소시킬 수 있다. 영혼이 0이 되면 버스트 판정과 구분되는 즉시 전투 패배로 처리하고 남은 효과와 차례를 중단한다.

## 4. 계약 플레이 흐름

1. 플레이어가 자신의 차례에 악마 덱을 선택한다.
2. 화면에 비용, 계약 후 남는 영혼, 전투당 남은 계약 횟수를 표시한다.
3. 플레이어가 확인하면 계약 가능 조건을 다시 검사한다.
4. 영혼 1을 지불한다.
5. 악마 덱에서 제시 가능한 카드 중 최대 2장을 중앙 선택 영역에 앞면 카드로 펼치고, 호버한 후보의 능력과 대가를 함께 표시한다.
6. 플레이어가 하나를 선택한다.
7. 선택한 악마 카드를 플레이어 앞 활성 계약 영역으로 옮기고 미선택 카드가 있으면 악마 버린 더미로 보낸다.
8. 선택한 악마의 즉시 효과를 처리한다.
9. 버스트·영혼 고갈·전투 종료를 확인한다.
10. 전투가 계속되면 지속 효과와 대가를 등록하고 적 차례로 넘긴다.
11. 이후 명시된 발동 시점마다 능력과 대가를 처리한다.
12. 전투가 끝나면 활성 계약과 전투용 악마 덱·버린 더미를 제거한다.

## 5. 계약 가능 조건

다음 조건을 모두 만족해야 계약을 시작할 수 있다.

1. 전투가 진행 중이고 플레이어가 정상 행동을 할 수 있다.
2. 카드 효과, 체인지, 다른 계약 선택을 처리 중이지 않다.
3. 이번 전투의 기본 계약 횟수를 아직 사용하지 않았다.
4. 플레이어의 현재 영혼이 계약 비용보다 많다.
5. 악마 덱에서 제시할 물리 카드가 최소 1장 있다.
6. 전투·런 상태가 계약 입력을 받을 수 있는 유효한 인스턴스다.

검사 실패는 영혼, 덱 순서, 사용 횟수, 차례와 UI 상태를 변경하지 않는다. 추가 계약을 허용하는 효과는 횟수 조건만 예외 처리하며 영혼 조건과 최소 후보 1장 조건은 그대로 적용한다.

## 6. 악마 덱과 수명

### 6.1 시작 덱 프로토타입 결정

새 런을 시작하기 전에 현재 해금 풀에서 서로 다른 악마 카드 2장을 제시하고 반드시 1장을 선택한다. 선택한 악마는 시작 악마 카드 덱에 추가되어 악마 덱을 최소 1장으로 보장한다. 선택하지 않은 악마는 시작 덱에 들어가지 않는다. 시작 선택은 계약이 아니므로 영혼과 전투당 계약 횟수를 소비하지 않으며, 선택 직후 결과를 저장한다.

DC-R01은 현재 `DemonContractCatalog`의 구현된 네 악마를 해금 풀로 사용해 결정적으로 서로 다른 2장을 만들고, 선택한 1장만 안정된 물리 ID와 함께 최초·현재 런 악마 덱에 넣는다. 선택 결과는 재시작과 `StartingDemonSelected` 체크포인트 캡처·복원에서 유지된다. 시작 후보의 별도 해금 데이터와 등장 가중치는 향후 밸런스 단계에서 정한다.

기존 호출부와 전투 화면을 깨뜨리지 않기 위해 선택 생성기를 주입하지 않은 `PlayerRunState`는 당분간 네 장 프로토타입 덱을 유지한다. 실제 새 런 진입 화면과 `StageProgressionRuntime`이 빈 덱·선택 생성기를 사용하도록 연결하는 작업은 DC-R05 범위이며, DC-R01 완료는 순수 도메인과 저장 경계 완료를 뜻한다.

과거 4장 구성은 완료된 구현 이력으로만 보존한다. 중복 카드와 등장 가중치는 상점에서 악마 카드를 획득하는 흐름이 구현된 뒤 다시 조정한다.

### 6.2 런 덱과 전투 덱

- 런 상태는 보유한 악마 카드의 안정된 정의 키와 물리 ID를 보존한다.
- 전투 시작 시 런 악마 덱 전체를 복사해 전투용 드로우 더미를 만들고 섞는다.
- 선택한 카드는 활성 영역, 선택하지 않은 카드는 전투용 악마 버린 더미로 이동한다.
- 추가 계약 시 드로우 더미가 부족하면 활성 계약을 제외한 버린 더미를 섞어 보충한다.
- 제시 가능한 물리 카드가 1장 이상이면 계약을 시작할 수 있고 최대 2장을 뽑는다.
- 전투 종료 시 전투용 위치만 폐기하고 런 악마 덱의 소유권은 유지한다.

이 구조에서는 첫 전투에서 버린 악마도 다음 전투에 다시 등장할 수 있다. 전투 중 카드 이동을 런 영구 제거로 해석하지 않는다.

### 6.3 계약 임시 카드와 소유권

- 바포메트의 오망성은 숫자를 합계에 포함하고 현재 전투의 덱·손·버린 더미를 순환한다. 전투 종료 시 모든 위치에서 제거한다.
- 파이몬이 추방한 카드는 현재 전투 동안 덱·손·버린 더미에서 제외하고 전투 종료 시 원래 소유권과 전투 시작 덱 구성을 복구한다. 플레이어 런 덱에는 제거를 반영하지 않는다.
- 벨리알이 가져온 카드는 현재 전투 동안 벨리알 계약 소유자의 카드다. 라운드 종료 시 그 소유자의 버린 더미로 보내고 전투 종료 시 원래 소유권으로 복구한다.
- 라운드 종료는 위 임시 상태를 제거하지 않는다. 하나의 상대와 벌이는 전투가 끝났을 때만 원상복구한다.
- 적이 같은 효과를 사용해도 방향만 반대로 적용하고 동일한 수명·복구 규칙을 따른다.

## 7. 공통 처리 우선순위

계약 효과와 카드 효과가 연쇄될 때 다음 순서를 사용한다.

1. 현재 실행 중인 단일 카드 이동·수치 변경을 끝낸다.
2. 명시적인 계약 대가와 직접 버스트를 처리한다.
3. 대가로 영혼이 0이 되면 즉시 전투 패배로 확정하고 남은 처리를 중단한다.
4. 행동 도중 숫자 버스트는 공개 카드 합으로 판정한다.
5. 라운드·전투가 끝났으면 남은 후속 효과를 중단한다.
6. 전투가 계속될 때만 다음 계약 훅이나 카드 효과를 처리한다.
7. 모든 효과와 선택이 끝났을 때만 차례를 넘긴다.

양측이 같은 효과 명령으로 동시에 버스트하면 전체 기획의 임시안대로 효과를 발생시킨 쪽이 패배한다. 계약 효과가 기존 카드 판정을 바꿀 때는 카드 이동을 복제하지 않고 카드 처리 결과 전후의 명시된 계약 훅만 사용한다.

## 8. 악마별 최신 규칙과 구현 이관

### 8.1 벨페고르 — 첫 수직 구현 대상

#### 능력

플레이어가 자신의 정상 차례에 히트를 선택하면 드로우 전에 덱 위 카드 한 장을 자신만 확인한다. 다음 중 하나를 고른다.

- 확인한 카드를 공개 상태로 히트한다.
- 확인한 카드를 덱 맨 아래로 보내고 이번 차례를 넘긴다.

#### 대가

상대가 스탠드한 상태로 플레이어의 다음 정상 차례가 시작되면 `차례 종료 시 자동 스탠드`를 예약한다. 플레이어는 그 차례에 허용된 행동 하나를 수행할 수 있지만 행동 완료 뒤 자동으로 스탠드한다. 덱 아래로 보내고 넘기기를 골라도 자동 스탠드한다.

#### 프로토타입 결정

- 덱 위 카드 정보는 플레이어에게만 표시한다.
- 히트 외 카드 사용·체인지는 미리보기를 발동시키지 않는다.
- 덱이 비어 정상 히트를 할 수 없으면 기존 히트 불가 규칙을 따른다.

벨페고르는 계약 공통 기반, 전용 선택, 덱 이동, 지속 대가와 정보 은닉을 한 번에 검증할 수 있어 첫 수직 구현 대상으로 정한다.

#### DC-03 구현 상태

- 히트 입력은 실제 드로우 전에 `BelphegorTopCard` 선택으로 보류되며, 공개 옵션에는 카드 ID·숫자를 담지 않는다.
- 실제 카드 ID·정의·숫자는 소유자 전용 `PlayerDemonContractPreview`에만 제공한다.
- 그대로 히트와 덱 아래 이동 모두 미리 본 물리 ID를 다시 확인한 뒤 처리한다.
- 상대 스탠드 뒤 시작된 다음 정상 차례에는 행동 완료 시 자동 스탠드를 한 번 예약하고 라운드 종료 시 초기화한다.
- 카드 사용·체인지는 미리보기를 만들지 않으며, 공개 합 중간 버스트와 전체 합 최종 승부 규칙은 기존 경계를 유지한다.

### 8.2 마몬

#### 능력과 대가

- 계약 즉시 6면체 주사위를 한 번 굴리고 결과를 공개한다.
- 자신의 차례에 일반 행동 대신 한 번 다시 굴리고 차례를 끝낼 수 있다.
- 결과가 6이면 즉시 계약 효과 버스트로 처리한다.
- 양측 스탠드 후 최종 합계 비교 직전에 1~5 값을 자신의 최종 합계에 더할지 선택한다.
- 더한 결과가 21을 넘으면 플레이어가 숫자 버스트한다.

#### 프로토타입 결정

- 주사위 값은 중간 공개 카드 합에 포함하지 않는다.
- 재굴림은 해당 차례의 일반 행동을 소비하며 결과를 되돌릴 수 없다.
- 값 적용 여부는 라운드마다 선택하고, 현재 주사위 값은 계약이 끝날 때까지 유지한다.
- 난수는 테스트 가능한 주입식 난수원을 사용한다.

#### 현재 구현과의 차이

- 현재 `MammonRuntimeState`와 주입식 주사위·최종 합계 선택은 재사용할 수 있다.
- 기존 차례 시작의 유지·재굴림 보류는 정상 행동을 소비하지 않으므로 최신 규칙과 다르다.
- 후속 구현에서는 재굴림을 일반 행동 후보로 옮기고 성공 시 즉시 적 차례로 넘겨야 한다.

### 8.3 레비아탄

#### 능력과 대가

- 플레이어가 리볼버를 사용하면 해당 리볼버 효과를 두 번 발동한다.
- 두 발동을 처리한 뒤에도 상대가 버스트되지 않았다면 플레이어 영혼 1을 잃는다.

#### 프로토타입 결정

- 각 리볼버 발동은 기존 단일 비공개 카드 추측과 정보 은닉 규칙을 그대로 사용한다.
- UI는 실제 비공개 숫자를 노출하지 않고 각 발동의 선언과 성공/실패만 표시한다.
- 대가로 영혼이 0이 되면 즉시 전투 패배다.
- 리볼버 사용 자체가 승인되지 않았다면 능력과 대가 모두 발동하지 않는다.

#### 현재 구현과의 차이

- 기존 DC-04는 실패 뒤 상대 공개 합 22 이상을 추가 판정하는 방식이므로 폐기 대상이다.
- 후속 구현에서는 리볼버 효과를 안전하게 두 번 실행할 수 있는 연속 처리 경계를 추가한다.
- 첫 발동이 전투를 끝낸 경우 두 번째 발동을 중단하고, 두 발동의 선언을 각각 새로 고르는지는 구현 명세에서 확정한다.

### 8.4 사탄 — 노션 v0.6 개정 규칙

#### 원문 공통 부분

- 계약 중 플레이어는 스탠드할 수 없다.
- 계약 중 플레이어는 숫자·카드·계약 효과로 버스트되지 않는다.
- 사탄 계약 카드 자체가 윗면·아랫면 상태를 가진다.
- 계약 카드는 윗면으로 시작하고 계약 소유자의 차례가 끝날 때마다 뒤집힌다.
- 윗면에서는 숫자 두 개를 선언하고 하나라도 상대 비공개 카드와 같으면 상대를 버스트시킨다.
- 아랫면에서는 상대를 강제로 히트시키고 공개 합이 21 이하라면 새 카드를 즉시 버린다.
- 카운터 종료 시 영혼 2를 잃는 위험이 있다.

#### 현행 결정

- 종말 카운트는 계약 직후 4로 시작한다.
- 계약 소유자의 차례 시작마다 1 감소한다.
- 0이 된 차례 시작 시 영혼 2를 한 번 잃는다.
- 기존 DC-06의 카운트 6·양측 차례 감소·계약 종료·별도 숫자 8/10 권능 카드는 과거 구현으로만 보존한다.
- 후속 구현은 활성 계약 카드 상태에 현재 면과 종말 카운트를 함께 보존한다.

## 9. 화면과 피드백

### 9.0 덱 오브젝트

- 일반 카드 덱 옆에 별도의 악마 카드 덱을 나란히 배치한다.
- 두 덱의 맨 위 카드는 각각 일반 카드와 악마 카드의 전용 뒷면이 보이게 한다.
- 일반 카드 덱과 악마 카드 덱을 호버하면 현재 포함된 카드 목록을 펼쳐 표시한다.
- 목록은 카드 구성과 수량을 확인하기 위한 정보이며 실제 뽑기 순서는 표시하지 않는다.
- 악마 덱 선택은 계약 시작 입력으로 사용하고, 호버 정보 확인만으로는 비용이나 상태를 변경하지 않는다.

### 9.1 계약 전 확인

- 현재 영혼 / 계약 비용 / 계약 후 영혼
- 이번 전투 계약 사용 여부
- 후보를 1장도 제시할 수 없는 경우의 불가 사유
- `확인`과 `취소`

### 9.2 후보 선택

- 중앙 선택 영역에 `발견` 방식으로 펼쳐지는 앞면 카드 최대 2장
- 악마 이름과 일러스트
- 즉시 효과
- 지속 능력
- 대가와 정확한 발동 시점
- 계약 후 남은 영혼
- 카드 호버 시 능력·대가 상세 표시
- 카드 자체를 선택하는 입력

후보가 공개된 뒤에는 취소 버튼을 제공하지 않는다. 다른 전투 행동, 카드 사용, 체인지와 재중복 입력은 잠근다.

루시퍼가 제공하는 추가 계약은 같은 연출을 사용하되 후보를 5장으로 늘린다.

### 9.3 활성 계약

- 선택한 악마 카드를 일반 카드와 같은 크기의 앞면 월드 카드로 플레이어 앞 계약 영역에 둔다.
- 활성 계약 카드를 호버하면 악마 이름, 능력과 대가를 함께 표시한다.
- 계약 확정 뒤 화면 구석에 `DEMON CONTRACT` 제목과 활성 계약·최근 결과를 담은 텍스트 상태 상자를 상시 노출하지 않는다.
- 사탄 카운터 또는 마몬 주사위처럼 변하는 값
- 최근 발동 결과
- 전투당 계약 사용 완료 표시

UI는 규칙을 다시 계산하지 않고 전투가 제공한 안전한 표시 스냅샷만 사용한다. 상대 비공개 카드와 덱 순서는 계약 UI에 포함하지 않는다.

#### DC-05~DC-07 구현 상태

- 비용 지불 전 화면은 현재 영혼·비용·계약 후 영혼과 확인·취소를 제공하고 전투 상태를 바꾸지 않는다.
- 현재 구현은 비용 지불 뒤 가용 카드 수에 따라 후보 1~2장을 만들고 이름·능력·대가를 표시한다. 한 장이면 버리는 카드 없이 활성화하고, 0장이면 비용·횟수·난수·차례를 바꾸지 않고 거절한다.
- 사탄 후보는 선택 가능하지만 현재 표시는 과거 카운트 6·별도 권능 면을 사용한다.
- 최신 규칙의 카운트 4·소유자 차례 감소·활성 계약 카드 양면은 아직 코드와 UI에 이관되지 않았다.
- 표시 모델은 벨페고르 예약 상태, 마몬 현재 주사위, 레비아탄 발동 조건과 안전한 최근 결과를 보존하지만, 계약 완료 뒤 이를 별도 상시 패널로 그리지 않는다.
- 벨페고르 덱 위 숫자는 `PLAYER ONLY`로 구분하고 상대 비공개 숫자·전체 합은 표시 모델에 포함하지 않는다.
- `GameScene`과 `CoreLoopTest`의 스크립트 UI를 1280×720·1920×1080에서 검증했으며 씬 직렬화는 변경하지 않았다.
- 적 활성 계약은 표시 모델에 `상대` 소유자로 보존하되 상시 패널에는 노출하지 않고, 적 벨페고르 미리보기는 공용·플레이어 화면 모델에 노출하지 않는다.

DC-M01에서 `GameScene`과 `CoreLoopTest`의 계약 완료 후 상시 텍스트 패널을 제거했다. 비용 확인창, 후보 선택창과 계약 규칙·활성 상태 데이터는 유지하며, 향후 월드 카드와 호버 상세가 해당 정보를 맡는다.

현재 스크립트 기반 계약 패널은 후보 1~2장의 가변 표시 모델을 소비할 수 있으나 이번 단계에서 실제 화면을 다시 검증하지 않았다. 시작 악마 2장 중 1장 선택 화면과 런 진입 연결, 덱별 뒷면, 덱 호버 목록, 중앙의 월드 카드 선택과 플레이어 앞 활성 계약 카드 배치는 DC-R05 이관 항목이다.

## 10. 1차 범위와 제외 범위

### 10.1 포함

- 별도 런 악마 덱과 전투용 악마 덱·버린 더미
- 엄격한 영혼 비용 조건과 전투당 1회 제한
- 후보 최대 2장과 필수 1장 선택, 단일 후보 허용
- 활성 계약 수명과 전투 종료 초기화
- 동일 악마의 별도 계약 인스턴스와 전투 종료 원상복구 기반
- 벨페고르, 마몬, 레비아탄, 사탄
- 카드 효과·버스트·영혼·차례와의 명시적 연동
- 독립 전투와 런 전투의 입력·표시·영혼 동기화
- 정보 은닉, 반복 재시작과 카드 소유권 테스트
- 광신도의 우선 악마 4종 계약 선택과 플레이어·적 대칭 효과 처리

### 10.2 제외

- 나머지 악마 8종과 오망성 전체 기능
- 루시퍼가 만드는 추가 계약
- 유물·강화에 의한 계약 횟수·비용 변경
- 상점 악마 카드 구매의 실제 구현
- 저장 파일과 덱 편집 UI
- 최종 일러스트·애니메이션·사운드·현지화
- 추가 계약을 실제로 발생시키는 루시퍼·유물과 악마별 세부 중첩 계산

광신도의 자율 계약은 DC-07에서 연결했다. 다른 적 프로필은 명시적으로 악마 덱을 받지 않으며 계약 후보도 생성하지 않는다.

### 10.1 광신도 계약 선택 기준

- 계약 가능한 첫 정상 차례에는 일반 히트·스탠드보다 계약 시작을 우선한다.
- 사탄은 계약 비용 지불 뒤 남은 영혼이 종료 대가 2보다 커서 대가 이후에도 생존할 때만 우선한다.
- 레비아탄은 자신의 손에 아직 사용하지 않은 리볼버가 있을 때만 우선한다.
- 현재 광신도 프로필은 최대 영혼 3이고 리볼버가 없으므로 사탄·레비아탄을 선택하지 않는다.
- 벨페고르와 마몬은 같은 우선순위를 사용하고, 전투 시드로 결정된 후보 순서를 동점 기준으로 삼아 같은 시드에서 같은 선택을 재현한다.
- 벨페고르는 공개 카드 합만으로 덱 위 카드를 유지·이동하고, 마몬은 1~2를 재굴림하며 최종 승부에서는 비공개 카드를 포함한 전체 합이 21 이하일 때만 주사위를 적용한다.

DC-08의 400개 고정 시드 기준에서 벨페고르·마몬은 각각 40~60% 범위에 들고 사탄·레비아탄은 0회였다. 이는 네 악마를 억지로 균등 선택하는 목표가 아니라 현재 영혼·보유 카드에서 실제 효용이 있는 선택만 분산하는 기준이다.

| 평균 계약 횟수 | 전투당 0.5~1.0회 |
| 계약 선택 시간 | 20초 이하 |
| 계약 대가로 인한 패배 | 원인 이해 가능 여부를 우선 기록 |
| 우선 악마 선택률 | 한 악마가 60%를 넘으면 후보 가치 재검토 |
| 광신도 자동 전투 종료 | 200회 플레이어 행동 안에 100% 종료 |

계약 사용률이 낮으면 효과 수치부터 올리지 않고 비용, 계약 후 남은 영혼, 기대 이득과 대가 발동 시점을 먼저 더 명확히 표시한다.

## 13. 완료 조건

- 계약 비용과 전투당 제한을 우회할 수 없다.
- 후보 최대 2장과 선택·버림·활성 영역에서 물리 카드가 복제되거나 유실되지 않는다.
- 일반·악마 덱의 전용 뒷면과 순서를 숨긴 호버 목록이 구분된다.
- 가용 카드 수에 따라 후보 1장 또는 2장이 중앙에 펼쳐지고 선택 카드가 플레이어 앞 계약 영역으로 이동한다.
- 후보와 활성 계약 카드의 호버 정보에 능력과 대가가 함께 표시된다.
- 네 우선 악마의 능력과 대가가 표시 문구와 같은 순서로 처리된다.
- 일반 중간 버스트는 공개 합, 최종 승부는 전체 합이라는 현행 규칙이 유지된다.
- 상대 비공개 정보와 실제 덱 순서가 화면·로그·적 AI에 새로 노출되지 않는다.
- 전투 종료·다음 전투·런 재시작에서 계약 상태가 남지 않는다.
- 오망성·파이몬 추방·벨리알 탈취가 라운드를 넘어 유지되면서 런 덱에는 남지 않는다.
- 같은 악마 계약이 서로 다른 물리 ID와 런타임 상태를 가진다.
- 자동·수동 검증 결과와 실제 담당 파일을 진행 기록·AI 활용·팀 역할 문서에 남긴다.
