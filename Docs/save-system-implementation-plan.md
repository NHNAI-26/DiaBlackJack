## 1. 구현 전략

파일 쓰기부터 시작하지 않는다. 먼저 저장 가능한 도메인 상태와 불변식을 고정하고, 메모리 저장소로 스냅샷·복원 왕복을 검증한 뒤 실제 디스크와 Runtime·UI를 연결한다.

```text
SV-00 문서 기준
→ SV-01 순수 스냅샷·검증
→ SV-02 버전 JSON·원자 파일·백업
→ SV-03 현재 런 캡처·복원
→ SV-04 체크포인트 조정·결정성
→ SV-05 새 게임·이어하기·실패 UI
→ SV-06 RF/사건 통합·재실행 회귀·기록 마감
```

## 2. 공통 보호 범위

- CoreLoop 전투 규칙과 적 AI 공정성
- 전투 손패·덱 순서·보류 선택 비저장 원칙
- HONG의 `RunFlow`·`Shop` 내부 구현
- Shim0Hwan의 아트·레벨 환경
- 기존 카드·악마 정의 키와 물리 ID 의미

- Packages, 외부 에셋과 Unity 생성 프로젝트 파일

새 종속성을 추가하지 않는다. `.unity`·프리팹 편집은 UI 단계에서도 실제 필요성과 직렬화 충돌을 확인한 뒤 최소화한다.

> **Notion v0.7 연계 원칙 (2026-07-29)**
> 적 프로필의 새 덱·능력·계약과 전투 중 생성된 독극물은 저장 대상이 아니다. 여섯 프로필 골드는 3·4·6·7·9·15로 확정됐지만 SV-06은 RF의 골드·상점 안정 상태가 실제 타입으로 구현된 뒤에만 연결한다. 문서 수치나 임시 전투 상태를 저장 DTO에 먼저 추가하지 않는다.

### 주요 파일

- `SaveLoad/RunSaveEnvelope.cs`
- `RunSaveSerializer.cs`
- `IRunSaveFileStore.cs`
- `SystemRunSaveFileStore.cs`
- `RunSaveRepository.cs`
- 저장 결과 타입과 EditMode 테스트

### 작업

1. 필드 기반 JSON DTO와 Mapper를 구현한다.
2. Enum을 안정 문자열 코드로 변환한다.
3. 기본·백업·임시 파일 이름을 한곳에서 관리한다.
4. 임시 기록·재검증·백업·교체 순서를 구현한다.
5. 각 파일 연산 실패를 주입할 수 있게 한다.
6. 기본 손상 시 백업을 읽고 둘 다 손상되면 명시적으로 실패한다.

### 완료 게이트

- SV02-U01~U08 통과
- 파일 단계별 실패에서 이전 기본 저장 보존
- 영구 데이터 경로 밖 쓰기 없음
- 새 패키지 없음

- 미래 스키마·콘텐츠 리비전 불일치·양쪽 손상·빈 레거시 파일을 서로 다른 결과로 분류한다.
- Unity MCP 대상 8/8, StageProgression 149/149, 전체 EditMode 491/491, 컴파일 오류 0건을 확인했다.

## 6. SV-03 — 현재 런 캡처와 복원

### 목표

현재 구현된 영혼·일반/악마 덱·스테이지·후보 생성 정보를 저장하고 새 세션으로 복원한다.

### 주요 변경

- `PlayerRunState` 읽기 전용 마지막 발급 ID 투영 또는 Snapshot API
- 검증된 상태 전용 복원 Factory
- `RunProgress` 안정 상태 캡처
- `RunRestoreFactory`
- `StageProgressionSession` 재구성 Factory

### 작업

1. 현재 런 상태를 스냅샷으로 캡처한다.
2. 일반·악마 카드 정의와 물리 ID를 복원한다.
3. 제거된 최고 ID 이후 발급 번호를 보존한다.
4. 현재 경로·스테이지 ID와 인덱스를 복원한다.
5. 루트 시드·순번으로 상대·보상 후보를 재현한다.
6. 전체 새 세션 구성 성공 뒤에만 Runtime 교체 후보를 반환한다.

### 완료 게이트

- SV03-I01~I07 통과
- 저장 전후 공개 런 상태 완전 동등
- 복원 실패 시 기존 세션 무변경
- 현재 CoreLoop·StageProgression 회귀 통과

### 완료 기록

- `PlayerRunState.Restore`가 현재 덱의 최대 ID보다 큰 마지막 발급 ID를 보존해 삭제된 최고 ID를 재사용하지 않는다.
- `RunProgress.Restore`는 현행 안정 상태와 스테이지 인덱스만 새 객체에 적용한다.

- 현재 `PlayerRunState`가 소유하지 않는 양수 골드는 묵시하지 않고 복원을 거부한다.
- Unity MCP 대상 7/7, StageProgression 156/156, 전체 EditMode 500/500, 컴파일 오류 0건을 확인했다.

### 완료 게이트

- 같은 체크포인트 반복 로드에 같은 후보

- 저장 실패 시 다음 콘텐츠 진입 차단

- 오래된 시작 선택, 중복 보상·종료, 잘못된 다음 콘텐츠는 도메인과 파일을 바꾸지 않는다.
- 반복 로드한 시작 체크포인트에서 같은 다음 상대 후보를 재현한다.
- 선택적 예약 ID의 `null`/빈 문자열 직렬화 차이를 정규화했다.
- 대상 8/8, StageProgression 180/180, CoreLoop 362/362, 전체 EditMode 542/542와 스크립트 진단 오류·경고 0을 확인했다.
- Runtime·메뉴·UI 연결과 실제 영구 경로 재실행은 SV-05, 상점·사건은 RF API 이후 범위다.

## 9. SV-06 — RF·사건 통합과 최종 검증

### 목표

실제 골드·상점·사건 상태를 체크포인트에 연결하고 프로세스 종료·재실행까지 검증한다.

### 선행 조건

- 시작 악마 후보 2장·1장 확정 상태와 성공 결과
- `PlayerRunState` 골드 구현
- HONG의 상점 방문·나가기 성공 상태와 공통 서비스 가격 단계 읽기 계약
- 사건 시스템이 있다면 사건 ID·완료 결과 API
- 정식 런의 다음 콘텐츠 결정 경계

사건이 아직 없으면 사건 저장을 구현 완료로 표시하지 않고 상점까지의 1차 완료와 사건 잔여 범위를 분리한다.

- 상점 나가기 완료 저장
- 하나 또는 둘의 서비스 이용 뒤 공통 가격 단계 저장·복원
- 사건 해결 완료 저장
- 보스 승리·패배 터미널 저장
- 10회 저장·종료·이어하기 반복
- 기본 손상·백업 복구 실제 파일 검증
- 전체 EditMode와 실제 앱 재실행
- 두 해상도·Console 확인
- 문서 4종과 공통 기록 마감

### 완료 게이트

- SV06-I01~I04 통과
- RF 통합 테스트와 전체 회귀 통과
- 실제 프로세스 종료 뒤 정확한 체크포인트 복원
- 후보·상품·사건 재추첨 없음
- 외부 에셋·오픈소스·패키지 기록 완료
